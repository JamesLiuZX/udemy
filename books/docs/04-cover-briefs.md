# Cover design briefs

Seven titles, one designer brief, one series. A human designer should be able
to quote and execute this whole set from this document alone, with no further
questions to the author. Per-book sections below give the specifics; this
header is what makes them a set instead of seven one-offs.

**Do not commission these one at a time.** Buy the series design once
(`docs/05-kdp-playbook.md` §3): one visual system, seven applications. The
payoff is that the author page reads as a publisher's list, which matters
more here than for a single title (see "Why a series system, not seven
covers" below).

---

## 1. The series system

**Author, every title:** James Liu.

**Interior identity to echo**, not copy verbatim onto a cover (a cover is a
different medium and gets to be bolder), but every design decision should
trace back to it:

| Role | Face / value |
| --- | --- |
| Headings, chapter numerals | TeX Gyre Schola (a Century Schoolbook cut) |
| Body reference | IBM Plex Sans / IBM Plex Mono |
| Accent colour | Ink blue `#1B4F8F`, the only colour that survives into the black-and-white interior |
| Overall register | Teaching-page restraint: white paper, printed ink, no gradients, no glassy cards, no heavy rounded corners, no emoji as decoration |

Translate that into a cover system built from: **serif display type in the
Schola family** (or a closely licensed equivalent if a designer's toolkit
lacks it) for title treatment, **ink blue `#1B4F8F` as the one recurring
accent** across all seven spines and front covers, a **consistent
typographic hierarchy** (title / subtitle / byline in the same relative
weights and positions on every cover), and **restraint over illustration**:
this is a shelf of field guides and management systems, not novels, so the
cover should look like it was designed by an editor, not generated. Every
title's cover uses the same grid, the same type system, and a distinguishing
element per book (a single icon, figure, or motif, not a stock photo) so the
seven read as a set on an Amazon author page or a bookshelf.

### Why a series system, not seven covers

Publishing several AI-assisted advice books under one new author account in
a short window is the exact surface pattern Amazon's mass-produced-AI
enforcement watches for (`docs/05-kdp-playbook.md` §1). The books are not
that: the craft system behind them is the proof. But a matched series design
is part of that proof too. Seven titles that visually cohere read as a
publisher's list; seven mismatched covers read as content-farm output. This
is a compliance signal as much as a marketing one.

### The no-AI-art rule

**No AI-generated cover art, on any of the seven.** Two independent reasons,
both non-negotiable:

1. **Consistency with the interior.** The interior typesetting and figure
   system is deliberately hand-built and free of AI-generated visuals
   (`docs/09-visual-standard.md`, mirrored in the course side's visual
   policy). A cover generated by an image model breaks that discipline at
   the one surface every buyer sees before anything else.
2. **It changes the KDP disclosure answer.** AI-generated cover art moves a
   title's AI-generated declaration at the KDP dashboard (`books/CLAUDE.md`
   §1, `books/docs/00-kdp-compliance.md`) from "AI-assisted" toward
   "AI-generated," which is a materially different, harder-to-defend
   declaration for a book already built on the AI-assisted claim being true.

A human-illustrated or typographic-only cover (type, colour, simple vector
shapes) is the brief. Photography, if used, must be real, licensed
photography, not a synthetic-media substitute.

### Simplified Chinese editions

All seven titles have a Simplified Chinese edition (`book-zh.yaml`,
`manuscript-zh/`). **Amazon KDP does not support Chinese-language paperback
or ebook publishing** (`docs/08-channels.md` §4), so the Chinese editions
route to Google Play Books, Apple Books, and direct/lead-gen distribution:
ebook-only, no print run and no KDP print-cover spec needed. Each Chinese
edition needs its own **ebook cover only**, at the same 2560x1600px spec as
the English ebook cover, with the title/subtitle re-set in the translated
type (Noto Serif CJK SC, matching the interior's CJK face) inside the same
series system. Do not attempt a print spine for the Chinese editions; there
is no channel that will print one. Per-book spine/wrap numbers below are
supplied anyway, in case direct print-on-demand for the Chinese market is
pursued later, but they are not part of the near-term commission.

### Standard specs, every title

| Asset | Spec |
| --- | --- |
| Trim | 6" × 9" (all seven; confirmed in each `book.yaml`) |
| Paper | White (KDP's non-colour interior default; confirms the `0.002252in/page` spine formula below) |
| Bleed | 0.125" on all outer edges (top, bottom, outside edge of front and back cover) |
| Spine width formula | `final page count × 0.002252 inches` (KDP's white-paper constant) |
| Full wrap width | `(6 × 2) + 0.25 (bleed) + spine width` = `12.25" + spine width` |
| Full wrap height | `9 + 0.25 (bleed)` = **9.25"**, constant across all seven |
| Ebook cover (English + each Chinese edition) | 2560 × 1600px, RGB |
| Audiobook square (English only, for KDP Virtual Voice / Spotify) | 3000 × 3000px, RGB |

Full wrap width and spine numbers below use each title's **final, locked**
page count, taken from the book's own `notes.md` (per-title status, most
recent entry) — not from `target_pages`, which is a planning band, not the
real count. **Recompute if the manuscript changes after this brief is cut**;
spine width does not round-trip forgivingly at these small page-count deltas.

## 3. Commissioning notes

- **Recompute before commissioning if any manuscript has changed** since
  this brief was cut (2026-08-12). Page counts are pulled from each book's
  `notes.md`, most recent status entry; verify against a fresh
  `python3 books/pipeline/build.py --book <slug>` if in doubt, since spine
  width is unforgiving at these page-count deltas (a page-count shift of
  10 pages moves spine width by roughly 0.0225").
- **English print (paperback + ebook) commissions first**, per the launch
  sequencing in `docs/05-kdp-playbook.md` §1: `stop-guessing` ships alone,
  the other six wait. There is no reason the series *design* can't be
  commissioned as one project covering all seven applications now, since
  the visual system is what needs to be locked once; individual title
  covers can be finalized as each book clears its author read-through.
- **Budget tier**: `docs/05-kdp-playbook.md` §3 references the $300-800
  per-cover tier as the reference market rate; a matched seven-title series
  from one designer should be quoted as a single project, not seven
  independent commissions, and should cost less per cover than seven
  one-offs would.
- **ISBN and ISBN placement**: whichever ISBN path the author chooses
  (`docs/08-channels.md` §6) affects the back-cover barcode area; confirm
  before finalizing the back-cover layout.
