@slide callout
kicker: The question worth asking about any near miss
::: callout What actually stopped this, not what should have stopped it earlier
Two different questions. This lecture is about the second one, and it
is the one you will actually need an answer to the next time something
of yours nearly goes wrong.
:::

@narrate
It is tempting to end the last lecture's story at "the scope should have
been narrower," and stop there. That is true, and it is also not the
most important thing the incident proves. The more important question is
what actually held when the first line of defence failed.


@slide two-col
kicker: Two guardrails, only one of which failed
## Scope versus action

::: cols
:: card bad
### The guardrail that failed
The credential's scope. It was wider than intended, and that is a real
failure worth fixing, covered in Section 8.3's worksheet.
:: card good
### The guardrail that held
The action level. Draft-only, decided in Section 6, before this
capability was ever imagined. It did not depend on the scope being
right.
:::

@narrate
This is the whole argument of Section 6, proven under real conditions
instead of just asserted in a lecture. A wrong scope is a mistake. A
wrong scope on an agent that can only draft is a mistake that stays
small, because the thing that actually causes harm, sending something,
was never possible in the first place.


@slide callout
kicker: The layered guardrail, named
::: callout Redundancy is not overcaution, it's the whole design
Scope limits what an agent can see. Action level limits what it can do
with what it sees. Approval gates, from Section 8.1, add a human step
even when action is allowed. Build more than one of these into
everything you make, because Section 8.4 proves you cannot always get
the first one right.
:::

@narrate
That sentence, "you cannot always get the first one right," is not
pessimism. It is the entire reason a single guardrail is never enough,
however carefully you think you set it.


@slide bullets
kicker: What changes in how you build, starting now
## Three habits from this section, carried forward

1. Run C08 on every addition, including the ones that feel too small to bother
2. Never let action level be the guardrail you assume is fine because scope looks fine
3. Treat draft-only as the default for any new agent, and earn your way up from there, not down

@narrate
Four agents, one real incident, and a scope error that never became a
disaster. That is the standard the rest of this course holds itself to.
Next lecture closes the section, and Section 9 turns to the number every
manager eventually asks for: what this actually costs, and what it
actually saves.
