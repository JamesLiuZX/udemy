@slide statement
kicker: The brief, in one sentence
## Pick one task you do every week and would rather not. Run this course's method on it, start to finish.

lead: Not a new idea to learn. The one method, run once for real, on something that matters to you.

@narrate
You have watched this method work four times against Priya's week. This
is where you find out it works against yours. Pick something real: not
a toy example, the actual task that eats twenty minutes you would rather
spend elsewhere. It does not need to be dramatic. A weekly status update
you copy from three systems by hand, a folder of receipts you sort every
Friday, an inbox rule you have meant to write for months: any of those
qualifies.


@slide bullets
kicker: The six steps, in order
## Everything you have already practised

1. Write the job description (C05): the job, scope, action level, ceiling
2. Build it in n8n: trigger, judgement, routing if needed
3. Test it against pinned, realistic data before spending a real call
4. Run a proper trial (C06), reading everything, for a length you decide up front
5. Run the guardrails worksheet (C08) if it touches anything new or sensitive
6. Log the real cost and time saved (C09), honestly

@narrate
Every one of those six steps is something you have already done at
least once in this course. Nothing here is new. What's new is that
nobody is handing you Priya's story bible to work from this time.


@slide callout
kicker: If you don't have an idea yet
::: callout Borrow the shape of one of Priya's four
Something you triage, something you extract from a longer document,
something you summarise on a schedule, or something you chase. Almost
every recurring task fits one of those four shapes.
:::

@narrate
Do not spend a week searching for the perfect task. A modest, real task
done properly beats an ambitious one left half finished, and that
sentence has been true since Section 1. If two candidates come to mind,
pick whichever one you can describe in a single sentence right now.
That sentence is the first line of your job description.


@slide bullets
kicker: What "done" looks like
## The finish line for this capstone

1. A filled-in C05 job description
2. A working n8n workflow, tested against pinned data
3. A logged trial, however short, with at least one output read critically
4. A one-sentence answer to "what did this actually cost, and what did it save"

@narrate
Next lecture works through a full example from start to finish, so you
can see the whole method run once more before you run it on your own.
