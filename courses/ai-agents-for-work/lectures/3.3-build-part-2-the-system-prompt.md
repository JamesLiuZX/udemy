@slide callout
kicker: The moment this stops being plumbing
::: callout Everything you have built so far moves an email. This node decides what it means.
The AI Agent node, and one paragraph you write yourself.
:::

@narrate
Click the plus after your trigger, search "AI Agent," and add it to your
canvas. You will see a box with three empty sockets underneath it: Chat
Model, Memory, and Tool. For this agent, you only need one. Attach a
model, click the search icon, and pick one from the list.

Why an AI Agent node, when the panel also offers plainer boxes that
just call a model? Because the agent node is the one built to hold a
standing instruction, and a standing instruction is what you are here
to write. The plain boxes send text and hand back text, once. The
agent node holds who it is, judges whatever arrives, and grows sockets
for memory and tools the day a later build needs them. You will use
those sockets in Section 6. Today two of the three stay deliberately
empty, and an empty socket on this canvas is the same kind of promise
as a missing send node: visible, checkable restraint.


@slide sidenote
kicker: Translating the jargon
## "Chat Model" is just the AI itself

::: split
:: main
n8n lists dozens of providers here: OpenAI, Anthropic, Google Gemini, and
smaller names beside them. Underneath the branding they all do the same
job for you, reading text and producing text back. You already chose
Gemini's free tier for this build back in Section 2.
:: aside Memory and Tool, skipped here
Memory lets an agent remember earlier messages in a conversation. Tool
lets it take an action, like searching the web. Your agent needs
neither: you are judging each email on its own, and it never acts, only
flags.
:::

@narrate
Click Google Gemini Chat Model, then Set up credential, and paste in your
API key from Section 2. That connects the thinking. Pick the small,
fast tier of the family, exactly as Section 2 argued: triage is a
sorting job, and sorting belongs to the quick models. Once the
credential saves, the box goes quiet, and the quiet is worth naming so
it does not unsettle you: nothing has been sent anywhere yet. n8n only
talks to the model when a run happens, so connecting the key costs
nothing and risks nothing. The agent still does not know what you want
it to think about, and that is the step you are about to take.


@slide two-col
kicker: The one paragraph that does the real work
## User Message versus System Message

::: cols
:: card bad
### User Message
What this specific email says. Changes every single run.
:: card good
### System Message
Who your agent is and how it should judge. The same every run, written
once by you.
:::

note: TODO-IMG screenshots/section-3/n8n-agent-prompt-and-system-message.png (Prompt field with subject/from/body expressions resolved against a real email; System Message textarea with the triage instructions)

@narrate
You might expect this part to be complicated. It is really just you
writing down, in plain sentences, the same judgement Priya already makes
in her head every morning. The rule you are following: don't write
clever instructions, write honest ones.

One small habit as you write into these fields: draft the briefing
somewhere you can think, a note or a document, and paste it in when it
reads well aloud. The text box does not care, but briefings written
directly into small boxes come out sounding like small boxes.

If the split feels abstract, borrow the human version. When a new
assistant starts, you brief them once: who we are, what matters here,
how I want questions answered. That briefing is the System Message.
Then every morning the post arrives, different every day, and they
judge it against the standing briefing. The post is the User Message.
n8n keeps the two in separate fields for a practical reason you will
appreciate for months: when the agent's judgement needs adjusting, and
it will, you edit one paragraph in one place, without touching a
single wire. Tuning an agent becomes rewriting a briefing, which is a
skill you already have.


@slide example
kicker: The actual system message used in this build
::: example Read it exactly as you would type it
"You are an inbox triage assistant for Priya Malhotra, a Client Services
Manager at a commercial insurance brokerage. For each email, decide if
it needs Priya's attention today. Flag it as urgent only if it is from a
real client and it concerns a renewal, a policy, a claim, a deadline, a
payment or a cancellation. Reply with one line: URGENT, with a reason,
or SKIP. Be conservative: promotional and internal messages are always
SKIP, even if they mention insurance topics in passing."
:::

@narrate
Notice what you did not write. No code, no special syntax, nothing an
engineer would recognise as a technique. Just a role, a decision, a
format for the answer, and one instruction about what to ignore. That
last sentence is doing more work for you than anything else in the
prompt. Leave it out, and you will find your model flags everything that
merely mentions the word insurance.


@slide table
kicker: Line by line
## Every sentence in that briefing has a job

| The line | What it is doing |
| --- | --- |
| "You are an inbox triage assistant for Priya..." | A desk to sit at: settles a hundred small judgement calls |
| "...decide if it needs Priya's attention today" | The actual job, in one clause |
| "...only if it is from a real client and concerns..." | The "urgent means" line from the job description, verbatim |
| "Reply with one line: URGENT, with a reason, or SKIP" | The predictable shape next lecture's routing branches on |
| "Be conservative: promotional and internal are always SKIP" | A priced trade: rare flags stay respected flags |

@narrate
Walk the paragraph with this table and the design stops looking like
luck. The role line quietly settles judgement calls you would
otherwise spell out one by one. The middle sentence should look
familiar, because it is the "urgent means" line of the job
description, nearly word for word: the document became the briefing,
and that is the whole transfer. The reply format line is engineering
you did without noticing, since routing can only branch on an answer
that arrives in a predictable shape. And the conservative line prices
a trade this course refuses to hide. This prompt will occasionally
skip a borderline email, and that is chosen, because the alternative
is a flag list so noisy nobody reads it, and an ignored flag list is
precisely how Ravi's message got lost the first time. A rare flag gets
respected. That is what the flag is for.


@slide callout
kicker: Where the User Message comes from
::: callout One field, three pieces of the email
Your Prompt field feeds the model the actual content: subject, sender
and body, pulled in with an expression referencing the trigger's output.
You are not typing the email in by hand. You are pointing at where it
already lives.
:::

@narrate
The mechanics: in the Prompt field, you build the message from the
trigger's output using the panel on the left, where every column of
that wire table you fetched last lecture is sitting, ready to be
dragged in. Drop in the sender, the subject and the body, with a word
of labelling around each so the model knows which is which. What you
must not do is type an example email into the field by hand. It will
work, beautifully, and it will keep judging that same imaginary email
forever while real mail streams past it: the pinned data trap from
Section 2 in its most convincing disguise. Point, never paste.


@slide bullets
kicker: Before you leave
## One live rehearsal

1. A real message, pulled in
2. A single paid run
3. The verdict, spoken, judged

@narrate
Before you leave this lecture, spend one real call. Fetch a test email
through the trigger, run the agent once, and read its one line answer
out loud, the way Priya would. URGENT, with a reason, or SKIP. If the
reason is sensible, you have just watched your own judgement come back
to you from inside a workflow, and that moment is worth having before
the routing goes in. If the reason is daft, even better: you have met
your first tuning loop a lecture early, and the fix is the same one it
will always be, a clearer sentence in the briefing. Either way the
agent cannot yet do anything with its decision. That is your next
lecture: routing.
