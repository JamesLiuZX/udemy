@slide title
## Worked Solution, Part One
kicker: Job description and build

@narrate
Every job description in this course has opened the same way: one
sentence stating the task plainly. This one keeps that habit. The task
is to work out which of three standard renewal documents, a stock
valuation, a fire safety certificate, a signed renewal form, a client is
still missing as their renewal date closes in, and say so before anyone
has to go looking for the answer by hand. That is the whole job.

What follows is the same six steps from 11.1, run once more end to end,
so you can watch the method work on something new before you run it on
your own. Nothing about this build is more advanced than what you have
already done. It is the same habits, aimed one more time at Priya's
paperwork instead of her inbox.


@slide example
kicker: Step one, the job description
## Filling in C05: the job, the scope, the action

::: example Filled from the C05 template, part one
**The job**: works out which of three standard renewal documents, a
stock valuation, a fire safety certificate, a signed renewal form, are
still outstanding for any client within 14 days of their renewal date.
**Scope**: reads Priya's renewal pipeline sheet only, the same one from
Section 5, now with three extra columns for document status. Writes
nothing back.
**Action**: read only, output only. A checklist, never an email, never a
change to the sheet.
:::

@narrate
Start with the sentence you always start with, because Section 1.4's
discipline does not get a pass just for being a demonstration. Notice
the verb: works out, not chases. That single word rules out half of
what this build could quietly tempt you into adding, and it is worth
reading back before you touch n8n at all.

Scope stays narrow on purpose. One sheet, the pipeline you already met
in Section 5, carrying three new columns Priya added herself for
document status. Nothing wider, and nothing written back to it: this
agent reads, it never edits the source of truth it depends on. Action
follows straight from that: read only, output only, so there is nothing
here for a mistaken click to send.


@slide example
kicker: Step one, continued
## Filling in C05: the ceiling and the trial

::: example Filled from the C05 template, part two
**Ceiling**: never decides a document has arrived on its own judgement,
only reports what the sheet's own column already says. Never contacts a
client: that stays Agent 4's job.
**Trial task**: one week, every flagged row checked by eye each morning.
:::

@narrate
The ceiling is where it is worth slowing down, same as always. This
agent never decides a document has landed. It only repeats what the
column already says, because a checklist that quietly starts guessing
stops being a checklist. And it never emails a client to chase a missing
signature, because that job already belongs to Agent 4, built with its
own draft-only guardrail back in Section 6. Two agents quietly doing the
same job with two different safety records is worse than one agent
doing it properly, and that is reason enough for you to leave chasing
out of this one entirely.

One week on trial. Every flagged row checked by eye each morning against
the sheet itself: short enough to actually happen, long enough to catch
a pattern rather than a fluke, the same balance every trial task in this
course has struck.


@slide statement
kicker: Step two, the build begins
## A schedule, a sheet, and three new columns

@narrate
Add a Schedule Trigger first, set to run every morning rather than Agent
3's once-a-week rhythm. Documents shift daily as a renewal date closes
in, and a Monday-only check would miss most of the week's movement.
After it, add a Google Sheets node, operation Get Row(s), pointed at the
same renewal pipeline from Section 5.2.

The only real change is what is sitting in the sheet now. Alongside
Client, Premium, Renewal Date and Status sit three more columns, one for
each document, each one either blank or marked Received the moment
Priya's assistant logs it. Pin a handful of rows here the way Section
5.2 did, so you can see real data flowing before you write a word of
prompt.

Attach an AI Agent node after the Sheets node, model connected the same
way as every build before it. The Prompt field hands the model every row
the sheet just read, seven columns per client, nothing filtered out yet.
What happens to that data next is entirely down to one paragraph you
write yourself, and that paragraph is the next slide.


@slide example
kicker: The actual system message used in this build
::: example Read it exactly as you would type it
"You are a renewal documents checklist assistant for Priya Malhotra at
Calloway and Finch. You are given a pipeline of rows: Client, Premium,
Renewal Date, Status, Stock Valuation, Fire Safety Cert, Signed Form.
For each open renewal within 14 days of its date, check the three
document columns. If any is blank, reply with one line: MISSING, naming
the client and every outstanding document. If all three already say
Received, reply: COMPLETE. Ignore any renewal further out than 14 days,
or already closed. Never mark a document received yourself: only report
what the columns already say."
:::

@narrate
Look at what that paragraph is actually doing. One sentence sets the
role. One sentence names exactly which columns to trust. One sentence
sets the window, fourteen days, not fifty, not one: a number chosen
because it gives Priya enough runway to actually chase something before
a renewal lapses. And the last sentence is the ceiling from the job
description, restated in the model's own instructions rather than left
to sit unused on a page nobody opens again.

That repetition is deliberate, not sloppy. A ceiling written once in C05
and never mentioned again is a ceiling the model never actually reads.
Say it twice: once for the human filing the job description, once for
the model doing the job.


@slide statement
kicker: Step three, wiring the output
## A Switch node, named the way Section 3.4 taught

@narrate
Add a Switch node after the agent, the same shape as Agent 1's build in
Section 3.4. One rule: does the answer contain the word MISSING. Send
that exit to a node named plainly, Flag for Priya, documents needed.
Everything else falls through to a second node named just as plainly,
Clear, no action needed.

Both are placeholders, exactly the way Section 3.4's were. The job
description says output only, so neither node sends anything or touches
the sheet. They exist so a stranger reading this canvas in six months
knows what each path means without asking you, which is the whole point
of naming a node the way this course keeps insisting on.


@slide table
kicker: Proof before a real call
## Four pinned rows, and a genuine boundary case

| Client | Renewal date | Stock valuation | Fire safety cert | Signed form | Agent output |
| --- | --- | --- | --- | --- | --- |
| Brightwell Manufacturing | 15 Sep | Received | Received | blank | MISSING: signed renewal form |
| Fenwick Haulage Ltd | 8 Sep | Received | blank | blank | MISSING: fire safety cert, signed renewal form |
| Marlowe and Sons Fleet Services | 5 Sep | Received | Received | Received | COMPLETE |
| Oakfield Retail Group | 30 Sep | blank | blank | blank | not flagged, outside the 14-day window |

@narrate
Pin this against a test date of 1 September and run it once, live,
before a single real call goes anywhere near it. Brightwell sits exactly
fourteen days out, right at the edge of the window rather than
comfortably inside it, and the agent still catches its missing signed
form. That is not an accident. A boundary case like that is exactly what
pinned test data is for: proving the ceiling holds at the edge, not just
in the easy middle.

Fenwick sits eight days out with two documents still missing, and the
agent names both rather than saying something vague like "some
documents outstanding." A checklist that makes Priya go and look again
has not actually saved her anything.

Oakfield is the row worth staring at longest. All three documents blank,
and the agent says nothing at all. Why? Because the thirtieth of
September is more than fourteen days from the pinned date, and the
system message explicitly says to ignore anything further out than
that. An agent that flagged every blank cell regardless of date would
bury Priya in noise a month before it mattered. One that only flags
what is actually close is doing the job the description actually asked
for.
