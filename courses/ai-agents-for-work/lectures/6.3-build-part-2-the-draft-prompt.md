@slide definition
kicker: A new kind of ceiling

::: definition Tone is a constraint too
The first three agents you built controlled what got written. This one
has to control how it sounds, because a client reads it, not just Priya.
:::

@narrate
Add an AI Agent node after your Sheets node, attach your Gemini model,
and open the Prompt field. The User Message hands over every row that
made it through your filter: client, contact, renewal date, days
remaining. You are not writing the email yourself, you are handing the
agent the facts and trusting the system message to shape them properly.

Why does tone need engineering when content did not? Because left to
their defaults, models write in a voice no real firm uses: a little
too enthusiastic, a little too padded, delighted to be following up.
Your clients know how your company sounds, and a chase that suddenly
sounds like software is a chase that gets screenshotted. The standard
to hold every draft to is simple and personal: read it aloud and ask
whether you would send it, word for word, under your own name, today.
Not whether it is fine. Whether it is yours. The system message gets
you most of the way there, and the trial's read-every-draft fortnight
is where you sand off the rest.


@slide example
kicker: The system message for this build
::: example Read it exactly as you would type it
"You are a follow-up drafting assistant. For each row, draft a short,
polite chase email asking for outstanding renewal documents. Name the
client and the renewal date. Do not mention the premium amount. Do not
imply any penalty or threat. You are drafting only, never write as
though the email has been sent. If information is missing, draft
without inventing it."
:::

@narrate
Read it as a client would, not as a builder: nothing in it is clever,
and everything in it is a boundary you decided before the first draft
existed. The next slide takes it apart line by line.


@slide table
kicker: Three sentences, three jobs
## What each line of the briefing controls

| The line | What it controls |
| --- | --- |
| "Name the client and the renewal date" | Content: the two facts every chase must carry |
| "No premium, no penalty, no threat" | Tone: what a client must never read |
| "Never write as though it has been sent" | Self-understanding: a drafter that knows it drafts |

@narrate
Three sentences in that prompt are doing three different kinds of work.
One controls content: name the client and date. One controls tone: no
threats, no premium figure sitting in a client's inbox as a number they
did not ask for. One controls the agent's own self-understanding: it is
drafting, not sending, and it should never write as though it already
has.

That last sentence sounds philosophical and is actually very
practical. A drafting model that believes it is mid-correspondence
invents history: "further to my last email", when there was no last
email, or "as discussed", when nothing was discussed. Every one of
those phrases is a small lie your client can catch, and the
never-write-as-sent line is what keeps them out. The missing
information clause works the same corner: if a row has no contact
name, the honest draft opens generically and Priya fixes it in four
seconds, which beats a warm "Dear Sam" addressed to a Sam the model
made up. Same escape hatch logic as Section 4, applied to
correspondence: give the model a dignified way to not know things.


@slide callout
kicker: Why the premium amount is banned from the email
::: callout A number a client didn't ask for reads like pressure
Even a neutral mention of "$18,400 renewal" in a chase email can land as
a nudge, whether or not you meant it that way. Cutting it costs you
nothing, because the actual renewal document already states it. This is
the same instinct as Section 1's blast radius, aimed at a sentence
instead of a system permission.
:::

@narrate
That is the whole prompt. It reads shorter than Section 5's, and it
should: the hard part of this build was never the writing. It was
deciding, in advance, exactly what a client should never see, and
saying so in one sentence rather than trusting the model to guess your
standards on its own.

And notice the stronger ban hiding in plain sight: the User Message
never hands the premium over at all. The filter passes client,
contact, date and days remaining, and the Premium column stays behind
in the sheet. The prompt's "do not mention" line is the second fence,
not the first. That two-layer pattern, exclude the data, then also
forbid the mention, is worth stealing for anything sensitive: a model
cannot leak a number it never received, and the instruction only has
to catch the case where the number sneaks in some other way. Wiring
first, briefing second. By now that order should sound familiar.


@slide bullets
kicker: Before you move on
## What you should have now

1. An AI Agent node drafting one email per row that needs a chase
2. A tone genuinely safe to send to a real client, on inspection
3. Zero premium amounts, zero threats, anywhere in the output

@narrate
Test the tone the cheap way before the next lecture: pin your filtered
rows, run the agent, and read its three drafts aloud, in your voice,
as if signing them. Mark anything you would rephrase, tighten the
briefing, run again for free. Tone converges fast under that loop,
usually in two or three passes, because you are not teaching the
model to write. You are teaching it to stop writing like software.

The draft now reads the way you want. Next lecture is where you make
sure it can never do anything except sit there waiting for Priya.
