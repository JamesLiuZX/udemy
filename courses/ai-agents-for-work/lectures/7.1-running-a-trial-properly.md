@slide statement
kicker: The wrong belief worth correcting
## "It worked the first three times" is not a trial. It is three data points that happen to agree with each other.

lead: A real trial is designed to find the failure, not to confirm the success.

@narrate
Every agent you built in Sections 3 to 6 worked the moment you tested it
against pinned data. That was always going to be true, because you built
the test data to be readable. A real trial has to include the cases you
did not think to plan for, because those are exactly the ones a real
week will hand you.

Why is "it worked three times" so persuasive when it proves so
little? Because agreement feels like accumulation. Three right
answers in a row feel like three pieces of evidence stacking up,
when what they usually mean is that Monday, Tuesday and Wednesday
happened to be easy in the same way. Priya's first week of triage
flags came back clean, every one, and the honest reading of that
week was not "the agent is trustworthy". It was "the inbox was
ordinary this week". The whole discipline of this section lives in
the gap between those two sentences, and the trial is the tool that
closes it: not more days of agreement, but a deliberate search for
the day that disagrees.


@slide two-col
kicker: Two ways to run the same trial
## Confirming versus testing

::: cols
:: card bad
### Confirming
Run it a few times, it looks right, move on. You are checking whether
you built the thing you meant to build.
:: card good
### Testing
Run it against the case designed to break it. You are checking whether
the thing you built actually holds up.
:::

@narrate
Go back to Section 3.5 for a second. The pinned inbox was not forty one
ordinary emails, it was forty ordinary ones and one that mattered,
deliberately buried. That is what a testing mindset looks like, and it
is the same mindset a proper trial needs, just aimed at real weeks
instead of pinned data.

Each of your four agents has a case designed to break it, and you
already know all four, because each build named its own; the next
slide gathers them in one place. A trial that happens to contain
none of them has tested the weather, not the agent, and the
practical move follows directly: when the breaking case does not
show up on its own, feed it in. Send yourself the borderline email.
Walk back a commitment in your own test call. You are allowed to
make the exam hard. That is what exams are for.


@slide table
kicker: The case designed to break it
## Every agent has one. You already know all four.

| Agent | The breaking case |
| --- | --- |
| Inbox triage | The borderline email even you hesitate over |
| Meeting notes | The commitment made, then walked back |
| Weekly report | A colleague editing the shared sheet mid-trial |
| Follow-up chaser | The client who already replied |

@narrate
Keep this table beside your trial log, because it is the difference
between waiting for a hard week and scheduling one. Each row is an
exam question you can set deliberately, and a trial that has passed
its own breaking case has earned something a lucky fortnight never
earns: you have watched this agent be wrong, or nearly wrong, and
watched what caught it.


@slide bullets
kicker: What "properly" actually means
## Four things a real trial does

1. Runs against real inputs, not just the pinned sample you built the agent with
2. Checks every single output, not a comfortable sample
3. Looks for the specific way this agent could go wrong, the exact thing the job description's ceiling exists to prevent
4. Has a defined length and a defined exit, decided before it starts, not extended informally forever

@narrate
That last point catches more people than any other. A trial with no
defined end quietly becomes "I'll always check it a bit," which is not
the same as either Trial or Review from Section 1.2. Decide the length
up front, in writing, before you start.

Notice that you have already done this four times if you followed the
builds: one week for triage, three or four calls for notes, three
Mondays for the report, two weeks of drafts for the chaser, each
written into a job description before its agent ran. The third rule
is where the ceilings come back too. Each trial watches for one
specific betrayal: a query marked resolved, an invented date, a
closed status the sheet never granted, a draft that reads like
pressure. You are not vaguely supervising. You are standing guard at
a named door, and knowing which door changes what you notice.


@slide callout
kicker: The honest reason this matters
::: callout A trial you don't really run is worse than no trial at all
It gives you the confidence of having checked, without the protection
of having actually checked. Next lecture turns this into a checklist you
fill in every time, so "properly" stops depending on how careful you
feel that particular week.
:::

@narrate
Hold onto the asymmetry underneath all of this, because it is the
reason the section exists, and it is the last thing this lecture
asks you to believe on argument alone: the next lecture's incident
shows it happening. Confidence without checking feels
identical to confidence with checking, right up until the day it
does not, and by then the unchecked agent has weeks of output behind
it. The checklist in the next lecture is how you make the difference
between those two confidences visible on paper. See you there.
