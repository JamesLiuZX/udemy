@slide definition
kicker: The gap this closes

::: definition You will not read every output forever
The moment you stop is exactly when this rubric has to start. Review,
from Section 1.2, needs its own discipline, and this is it.
:::

@narrate
Trial worked because Priya read everything. Nobody reads everything
forever, and nobody should have to. Once an agent earns its way onto the
Review rung, checking becomes sampling, and sampling only works if the
sample is chosen honestly.

Honestly is the hard word in that sentence, so ask it plainly: which
run gets checked, and who decides? Left to instinct, you
will sample the outputs that were already on your screen, skip the
weeks you were busy, and gravitate to runs that look interesting,
which are precisely the ones drift does not live in. So take the
choosing away from yourself: Section 1.2's die roll, or anything
equally blind, picks the run, and a ten minute calendar slot on
Friday picks the time. A spot check that depends on remembering and
choosing is two failure points pretending to be a habit. Booked and
blind, it is neither.


@slide table
kicker: How much to check, by volume
## The sampling rule from C07

| Agent's volume | Sample |
| --- | --- |
| Daily | One run a week, chosen at random |
| Weekly | Every run, until twelve pass with no failure |
| On demand | One in five, or after any prompt change |

@narrate
Read the middle row again: a weekly agent like Agent 3 stays fully
checked for twelve straight weeks before sampling even begins. That is
not overcaution, it is roughly the length of trial season for a renewal
pipeline, long enough to see a sheet actually get edited by someone else
at least once.

The rates differ because evidence accrues per run, not per day. A
daily agent hands you thirty verdicts a month, so a random one each
week keeps a real finger on it. A weekly agent produces four, which
is why it stays fully read for so long: sampling four outputs would
be a ritual, not a check. And the third row's trailing clause, after
any prompt change, is the one to underline. Any edit to the briefing
resets part of the trust, because the agent you checked is no longer
quite the agent that is running. The you-in-three-months from
Section 6.4, adding one small thing on a busy afternoon, is exactly
who that clause exists for.


@slide bullets
kicker: The five questions, every sampled run
## What C07 actually asks

1. Facts: does everything in the output appear in the source data?
2. Scope: did the agent stay inside its job description's boundary?
3. Ceiling: was the ceiling respected, no action it wasn't allowed?
4. Tone, where it applies: comfortable if a client or director saw this exactly?
5. Drift: does anything look different from a month ago, for no reason you can name?

@narrate
Question five is the one built directly from Section 7.3. A moved row is
exactly the kind of thing "drift" is designed to catch on a Review-rung
agent that nobody is reading in full anymore.

Run the five once, out loud, against a sampled chaser draft, and feel
how mechanical it is. Facts: the renewal date in the draft, found in
the sheet, cell for cell. Scope: the draft concerns a renewal client,
nothing else. Ceiling: read it once looking only for money and
pressure, and find neither. Tone: read it aloud as if signing it,
the Section 6 test, unchanged. Drift: put it next to a draft from a
month ago and ask what is different, and whether you can name why.
Ten minutes, five verdicts, and the useful discipline is writing
Pass next to each question rather than nodding: a nod cannot be
audited in March, and a filled-in rubric can.


@slide callout
kicker: What one Fail actually means
::: callout Not broken. Not trusted enough yet, in this one specific way
Log what happened, move that failure mode back to Trial until you
understand its cause, and re-test against the exact case that failed
before you call it fixed. Do not quietly patch the prompt and hope.
:::

@narrate
The protocol in that box is the difference between fixing and hoping.
A quiet prompt patch is an untested change to a system you have just
learned not to fully trust, made in response to a failure you have
not yet explained: two unknowns multiplied. Moving the failure back
to Trial costs you a week of closer reading, and re-testing against
the exact case that failed is what proves the fix fixed something,
rather than the failure simply not recurring on its own. Machines
get regression tests. Your agents deserve the plain-English version:
the thing that broke it once gets run again, on purpose, before
trust resumes.

Fill in C07 against one of your own agents this week, even if you have
not moved it to Review yet. Next lecture names the failure modes worth
watching for before you meet them for the first time.
