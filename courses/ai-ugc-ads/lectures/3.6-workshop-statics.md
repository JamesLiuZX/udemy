## B03: the batch generation prompt system

```text
FOR EACH ANGLE MAP ROW:

1. Subject: product + scene, matched to the angle's rung
2. Brand lock: hex code + reference image, never a colour word alone
3. Text rule: baked in only if one word or a bare number.
   Everything else: generate clean, overlay after
4. Face rule: only if the angle genuinely needs one
5. Type: packshot (locked reference) or lifestyle (feeling, not fact)
```

@narrate
This is the actual template, and every line traces back to a specific
lecture you've already sat through.

Subject and scene come from the angle map itself. The brand lock is
Section 3.3. The text rule is Section 3.4. The face rule is Section 3.3
again, applied per angle. And the packshot-or-lifestyle call is Section
3.5. Run all twenty rows through these five questions, and you're not
guessing at a prompt, you're filling out a checklist you already own.

Save this template somewhere you'll actually find it again. The next
product you brief, and the one after that, start from the same five
questions, not from a blank page and a hope that you remember what went
wrong last time.

## The order that works, and roughly how long each part takes

| Step | Time | What "done" looks like |
| --- | --- | --- |
| Translate 20 angle rows into prompts | 20 min | Five questions answered per row |
| Generate the batch | 5-10 min | Twenty statics back |
| Colour and product check | 10 min | Flag anything off-brand or off-spec |
| Regenerate flagged statics | 10 min | Fixed, not the whole batch redone |
| Add overlay text where needed | 15 min | Every exact claim added afterward, not baked in |

@narrate
About an hour, total, and notice most of it isn't generation time at all.
It's the checking and fixing this section spent five lectures teaching
you to do properly.

If your first batch comes back with real problems, seven or eight statics
needing fixes, don't read that as a bad batch. Harlan's did too. Read it
as confirmation that the checks in this workshop are catching exactly what
they're supposed to catch.

Notice, too, that the regenerate step only touches the flagged statics,
the same discipline from Section 3.3. If you find yourself regenerating
all twenty because a few came back wrong, you've slipped back into the
habit this whole section was built to break.

## Two shortcuts, same as Section 2.6's, showing up again

::: cols
:: card bad
### The shortcut
- Skip the reference image, describe the colour in words
- Bake in the exact claim because it's faster than a design tool
:: card good
### Why it costs you
- Batch two problem, again: colour drift on regeneration
- Batch two problem, again: garbled text on anything longer than a word
:::

@narrate
Both of these mistakes are the exact ones Harlan's first batch already
made. Skip the reference image and describe a colour in words, and you'll
get colour drift, for the same reason it happened in Section 3.2. Bake in
an exact claim because the design tool feels like an extra step, and
you'll get the same garbled text on the same kind of line.

You've already watched both of these fail once. That's the actual value
of doing this workshop after the section instead of before it. If this
were the first lecture in Section three rather than the last, both
mistakes would feel like reasonable shortcuts instead of familiar traps,
and you'd learn the same lesson Harlan did, the expensive way, on your own
batch instead of hers.

@slide callout
kicker: An honest note on the result

::: callout Be straight about this
A batch with zero problems on the first try is rare, not the standard to
expect. ==What matters is catching what's wrong before it reaches a
test==, not generating perfectly the first time.
:::

@narrate
One honest expectation to set before you start.

Even with every check built in from the start, some statics will still
need a fix. That's not this workshop failing. It's the same shape of
result Harlan got, and the actual measure of success isn't a perfect first
pass, it's whether every problem gets caught here, before Section seven's
test spends real money finding it instead.

Measure yourself against that standard when you finish, not against a
tidy number. Twenty for twenty on the first try would be a nice surprise.
Twenty for twenty after one careful regeneration pass is the actual goal,
and it's the same result either way by the time this batch is ready to test.
