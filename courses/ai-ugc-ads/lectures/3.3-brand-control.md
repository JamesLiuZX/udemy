@slide statement
kicker: Section 3 · The moment Dana caught it
## Dana scrolled to the fourth static and stopped. That sock wasn't Harlan Navy. It was royal blue.
lead: Brand control (checking a generated image against your real colours, logo and product) is narrower work than regenerating twenty images from scratch.

@narrate
Dana was scrolling through the new batch on her lunch break, half-checking,
half just looking, when the fourth static stopped her. The sock in it was
blue, definitely blue, but it wasn't Harlan Navy. It was a lighter, more
generic royal blue, the kind any supermarket brand could use. She kept
scrolling. Six more statics had the same problem.

The fix isn't starting over. It's smaller than that, and it's worth seeing
exactly how small.

Thirteen statics already held the colour correctly. Regenerating all
twenty to fix seven would throw away work that was already right. The
actual job is narrower: lock down what "correct" means precisely enough
that a second, smaller batch can't drift the same way.

This distinction matters beyond just saving generation time. Treating a
partial failure as a reason to start over is a habit that scales badly.
On a real account, running dozens of batches a month, that habit is the
difference between an afternoon of fixes and a permanently slow process.

@slide code
kicker: The fix
## What changed between batch one and batch two

```text
BATCH ONE PROMPT
"...Harlan Crew Sock in navy..."

BATCH TWO PROMPT
"...Harlan Crew Sock, hex #1B2A41 exactly, matched to
attached reference image, no colour interpretation..."

RESULT: 7 of 7 regenerated statics on brand colour.
Twenty of twenty now correct.
```

@narrate
Here's the actual change, and it's smaller than "colour drift" sounds like
it should require.

"Navy" is an instruction a model can interpret several honest ways. A hex
code, attached to a reference image and paired with an explicit
instruction not to reinterpret it, isn't. Regenerate just the seven flawed
statics with that tighter prompt, and Harlan's batch goes from thirteen of
twenty to twenty of twenty, without touching the thirteen that were
already fine.

Keep the reference image itself somewhere permanent, not just pasted into
one prompt and forgotten. The next batch, and the one after that, should
start from the same locked reference, not a fresh description written from
memory. That's how "Harlan Navy" stays one specific colour across months
of batches instead of drifting a little every time someone redescribes it.

## Colour is easy. Product accuracy is the harder check

::: cols
:: card bad
### What to actually check
- Does the sock in the image match the real product's cut and texture?
- Has the generator quietly "improved" a design detail?
- Would Dana recognise this as the product she actually sells?
:: card good
### Why colour alone isn't enough
- A statically perfect navy on a subtly wrong-looking sock still fails
- Generators optimise for a pleasing image, not product fidelity
- Nobody catches this by checking the hex value alone
:::

@narrate
Colour is the easiest brand-control check, which is exactly why it's
tempting to stop there. It isn't the only one that matters.

A generator is optimising for a pleasing image, not for matching Harlan's
actual product. It can quietly round off the exact cut, smooth a texture,
or invent a detail that wasn't in the reference at all, and none of that
shows up if the only thing you checked was the hex code. The real
question, every time, is whether Dana would recognise the sock in the
image as the one she actually sells.

This check takes real product knowledge, which is exactly why it can't be
fully delegated to a generic checklist. Whoever runs it needs to have
actually held the product, the same way Dana would notice a subtly wrong
cuff in half a second that a checklist item would never think to ask about.

@slide definition
kicker: When a face enters the frame
## The uncanny valley, defined for this use case

::: definition Key idea
The **uncanny valley** is the discomfort a viewer feels when a face is
almost, but not quite, right: proportions slightly off, an expression that
doesn't track, skin that reads as too smooth. It's stronger for faces than
almost anything else generated, because humans are unusually well-tuned to
spot a wrong one.
:::

::: example A fast test
Show the image to someone for two seconds, then ask what felt off. If they
can't say, but something did, that's the uncanny valley working exactly as
badly as it always does.
:::

@narrate
The moment a lifestyle static includes a face, the risk profile changes
completely, and it's worth naming why.

Humans are unusually good at detecting a face that's almost right but not
quite: proportions a little off, an expression that doesn't track the
scene, skin that reads as too smooth to be real. That's the uncanny valley,
and it doesn't need to be dramatically wrong to work against you. A face
that's ninety-five percent right often reads worse than one that's
plainly stylised, because ninety-five percent right is exactly what
triggers the discomfort.

This is a genuinely different failure mode from the colour drift a few
slides ago. A wrong hex value is a fact you can check against a reference.
An uncanny face is a feeling most viewers can't name, which makes it
harder to catch on a checklist and easier to miss until real spend has
already gone against it.

@slide callout
kicker: The honest limit

::: callout Be straight about this
Sometimes the safest brand-control decision for a face is not generating
one at all. ==A product shot with no face rarely feels wrong. A face that's
almost right often does==.
:::

@narrate
Here's the honest call this section doesn't want to avoid.

If a face isn't earning its place in an angle, the safest move is to leave
it out. A clean product shot with nobody in frame essentially never
triggers this problem. A face that's almost right, sitting in a batch
next to nineteen other statics, is the one thing a viewer will remember
for the wrong reason. You'll meet a more deliberate answer to faces in
Section four, where video needs one on purpose, handled properly rather
than as a side effect of a product shot.

Ask yourself, honestly, whether the angle actually needs a person in it,
or whether a person just felt like the default choice. "The 15-20 spec" and
"not just for flights" from the angle map don't need a face at all. "A
nurse's honest review" probably does. Not every row on that map should get
the same answer.

## Which rows actually need a face

| Angle | Needs a face? | Why |
| --- | --- | --- |
| The 15-20 spec | No | The spec is the whole argument, a face adds nothing |
| Not just for flights | No | A myth-bust works on the product alone |
| A nurse's honest review | Yes | Trust is the point, and trust needs a person |

@narrate
Do you actually need a person for what this angle is arguing? Run that
question down your own angle map before you generate a single face, and
you'll usually find the honest answer is no more often than it's yes.
