## You don't need five different ads. You need one shot list that produces every export you actually need.
lead: Three lectures of platform-specific detail collapse into one matrix you fill out once per angle.

@narrate
Three lectures back, you were checking Meta's safe zones. Two lectures
ago, it was Spark Ads authorization. Last lecture, a skip button. None of
that has to live in your head at once, because none of it changes the
actual shot.

What changes is only the export. Generate and film in full-screen
vertical, the way Section 5.1 already argued for, and every placement in
this section becomes a crop or a caption adjustment, not a reshoot.

Why does this deserve its own lecture, rather than a slide tacked onto
the end of 5.3? Because without it, the natural instinct is to treat each
platform lecture as a separate production task, a Meta cut, a TikTok cut,
a YouTube cut, three times the work for one angle. That instinct is
wrong, and it's expensive enough in real hours that it's worth a lecture
of its own to correct.

Think back to Section 4.6's workshop. You already produced three ads
there. This lecture asks you to look at those same three files again,
not to make anything new, and work out exactly how far each one already
gets you across every placement in this section.

@slide table
kicker: The matrix
## One angle, mapped to every placement

| Placement | Source needed | Extra step |
| --- | --- | --- |
| Meta Feed | Centred crop of the 9:16 master | None beyond the crop |
| Meta Stories / Reels | The 9:16 master, direct export | Check safe zones from 5.1 |
| TikTok | The 9:16 master, native cut | Spark Ads authorization from 5.2 |
| YouTube Shorts | Same TikTok export, reused | None |
| YouTube in-stream | A separate cut, if intent justifies it | Front-load the hook inside the skip window |

@narrate
Fill this out once per angle, and notice most of the row is repetition,
not new work. Four of five placements share one master file. Only the
in-stream row, and only when Section 5.3's intent test says it's worth
it, asks for a genuinely separate cut.

That's the actual point of building this matrix instead of improvising
per platform. It turns "where does this run" into a checklist you fill
out in minutes, not a decision you re-litigate for every single ad.

Notice, too, what the matrix quietly assumes: that you generated in
full-screen vertical from the start. If you didn't, every row above gets
harder, because you're reframing up instead of cropping down, exactly
the costly direction Section 5.1 warned you about. The matrix rewards a
decision made at generation time. It can't undo one made the wrong way
round after the fact.

Run this same table for every angle in a batch, not just your favourite
one. The whole point of Section 1.4's volume argument was never spending
your effort on a single ad. Applying that same discipline to export work
is what keeps a twenty-angle batch from turning into twenty separate,
one-off production decisions instead of one repeatable pass.

@slide code
kicker: The one thing worth automating
## A naming convention that survives the export

```text
harlan_houreleven_v1_9x16.mp4
harlan_houreleven_v1_4x5.mp4
harlan_houreleven_v1_tiktok.mp4
harlan_houreleven_v1_instream.mp4

<brand>_<angle>_<version>_<placement>.mp4
```

@narrate
One habit worth building now, before the batch gets larger than four
files. Name every export by angle, version and placement, consistently,
from the very first ad you ever produce this way.

This isn't busywork. Section 7.3 builds a whole naming and asset-library
standard on top of exactly this pattern, and it's far easier to start
consistent than to rename a folder of forty files six weeks from now
because nobody could tell which export was which.

Notice the convention encodes exactly the information a later decision
will need: which angle, which version, which placement. Nothing about
performance, nothing about the claim inside it. That's deliberate. A
filename is for finding a file fast, not for remembering what made it
good. That judgement belongs in the scorecard from Section 8.5, not
buried inside forty characters of a filename nobody will read carefully
under pressure.

Ask yourself, honestly: could you tell, right now, which of your
existing exports is which without opening every single one? If the
answer's no, that's not a small inconvenience. It's the exact failure
mode Section 8's results reading depends on you avoiding, because a
scorecard is useless if you can't confidently match a winning result back
to the specific file that earned it.

@slide callout
kicker: The honest limit

::: callout Be straight about this
This matrix handles format. ==It does not replace the platform-specific
judgement from 5.1 through 5.3, confirm current specs before every
campaign, the same discipline this whole section has asked of you==.
:::

@narrate
One honest limit on what a matrix like this can actually do for you.

It tells you which file goes where. It doesn't tell you whether Meta's
safe zones moved, or whether your Spark Ads code is about to expire, or
whether an audience is intent-driven enough to justify a separate
in-stream cut. Those are still judgement calls, made fresh, the way the
last three lectures taught you to make them. The matrix removes the
busywork around that judgement. It was never going to remove the
judgement itself.

That's a distinction worth being honest about, because it's tempting to
treat a checklist like this as a substitute for staying current. It
isn't. Revisit the platform-specific rows in this matrix on the same
quarterly rhythm the last three lectures already asked of you, not
because the matrix itself changes, but because what belongs in each cell
does.
