@slide table
kicker: The honest state
## What's reliable now, and what still needs a human check

| Capability | State |
| --- | --- |
| Photorealistic product scenes | Strong, across most leading generators |
| Short text: taglines, single words | Much improved. Multiple tools now handle this reliably |
| Long text: paragraphs, dense layouts | Still weak. Errors compound with every added line |
| Exact brand typography, logos | Still unreliable across the board |
| Run-to-run brand consistency | Still poor without deliberate curation |

@narrate
Here's the honest split, and it's more nuanced than "AI images are good now"
or "AI images can't be trusted." Which is it actually? Both, depending
entirely on which specific claim you're checking.

Photorealistic scenes are strong across most of the leading tools. Short
text, a tagline, a single word, a number, has genuinely improved to the
point of being usable directly, which wasn't true even a couple of years
earlier. But long text, and this matters a lot for a spec-driven brand like
Harlan's, is still weak: every additional line of text is another chance
for the model to drop a word or misplace a character. And getting an exact
logo or brand typeface right, or getting the same brand feel twice in a
row without curating it yourself, is still not something you can trust
unattended.

@slide definition
kicker: The specific finding on text
## Short beats long, reliably

::: definition Key idea
Text rendering hasn't just "improved". It's improved unevenly: short,
simple text is now close to solved. Long text and dense layouts remain
genuinely hard, because every extra glyph the model has to place correctly
is another independent chance to get it wrong.
:::

::: example The practical workaround
Generate the image clean, with no text baked in, then add your exact copy
in a design tool afterward. This is more reliable than any generator's text
feature for anything longer than a few words, and it stays true regardless
of which specific tool wins next quarter.
:::

@narrate
There's one finding worth being precise about, because it changes how you
actually work: text rendering hasn't uniformly improved. It's improved
unevenly.

A single word or a short tagline is close to solved territory now, across
several serious tools. A full sentence, a paragraph, or a busy layout with
several text regions is still genuinely hard, because each region the
model has to render correctly is an independent chance to get something
wrong. Think of it as compounding odds: get one word right ninety-nine
times out of a hundred, and a five-word line still fails noticeably more
often than a one-word line does.

The practical answer, and you'll build this properly in Section 3.4, is to
generate the image clean and add exact copy afterward for anything longer
than a few words. That workaround stays true no matter which tool is
winning the benchmark this quarter, because it doesn't depend on the
generator's text feature at all.

@slide two-col
kicker: What this means day to day
## Trust by default, versus verify every time

::: cols
:: card good
### Trust by default
- A clean product scene with no text
- A short, simple tagline or number
- General photorealism and lighting
:: card bad
### Verify every single time
- Any exact brand colour or logo
- Any spec number rendered as on-image text
- Consistency across more than one or two images in a batch
:::

@narrate
Here's the practical rule to actually work by.

Trust the clean scene and the short tagline by default, spot-checking
rather than scrutinising every pixel. Verify, every single time without
exception, anything that's an exact brand colour, an exact logo, a spec
number rendered as text, or consistency across more than a couple of
images in one batch. You'll see exactly why that verification step matters
in the next few lectures, because Harlan's first real batch fails on two
of those exact points.

Most marketers who've tried batch AI image generation report the same
frustration: real adoption, but real difficulty turning it into work they
can actually ship. That gap almost always traces back to skipping this
exact verification step, not to the generation itself being unusable.

One more honest limit, and it applies to me as much as it applies to you.

Whatever specific tools get named in the next few lectures were checked
against their actual current capabilities at the time of writing, not
recalled from memory or assumed. Do the same before you brief a real
batch. Five minutes confirming a tool still does what you think it does is
cheaper than a batch built on a capability that quietly changed.

This isn't a one-time check, either. Build it into a habit: before any
batch that matters, spend five minutes confirming the specific claim
you're relying on, whether that's a text-rendering feature, a consistency
tool, or anything else this course names. Tools in this category move
quarter to quarter, not year to year.
