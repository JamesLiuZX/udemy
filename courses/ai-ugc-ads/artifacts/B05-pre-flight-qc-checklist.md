# B05 · The Pre-Flight QC Checklist (Brand, Claims, Disclosure, Rights)

Part of *AI UGC Video Ads*. Built in lecture 6.6 and assembled from lectures 6.1
to 6.5. Use it to run every batch of generated ads through four checks, each with
one named owner and one moment, before anything is uploaded or any money is spent.
It is the gate that Section 7 (testing) assumes every ad has already cleared.

This is a checklist of questions and evidence. It is not legal advice and it does
not say what is required in your market. Rules on claims, AI disclosure, music and
likeness differ by platform, country and product category, and they change. The
person named for each check confirms the current position for themselves, with
qualified advice where a claim or a rule is in doubt.

---

## 1. How to use this

1. **Run it on a real batch:** the statics from B03, the three videos from B04, or
   both. Every ad, not a sample.
2. **Name the owner of each of the four checks before you start** (section 3). A
   review gate only works if it is enforced: if nobody has the authority to hold a
   batch back, you have a suggestion, not a gate.
3. **Run the checks at three checkpoints,** not once at the end. The total checking
   is the same, moved earlier, where each catch is cheaper (section 4).
4. **Expect failures.** A batch that passes all four checks on the first run is not
   the norm. In the course's own example batch, two of the four checks failed on
   the first pass. A failure caught here is the checklist working.
5. **Record every catch.** Draft, what caught it, rewrite (section 6). The log is how
   the next batch gets better.
6. **Nothing ships on a "pass with an asterisk."** If a line fails the claims check,
   a disclaimer does not fix it. Only a different sentence does.

## 2. The four categories of unshippable (lecture 6.1)

| Category | What it looks like | Where you learned the fix |
| --- | --- | --- |
| Claims overreach | A number, an outcome or a medical claim nobody can defend | Lecture 6.2 |
| Rights gap | An unlicensed voice, face or piece of music behind the ad | Lectures 4.1 and 6.4 |
| Brand or product drift | The product on screen is not quite the real one | Lectures 3.3 and 4.4 |
| Missing disclosure | AI-generated or AI-edited content shipped without a label a platform requires | Lecture 6.3 |

The order of the four checks is deliberate: cheapest fix first, hardest to reverse
last.

## 4. Three checkpoints (lecture 6.5)

| Checkpoint | Checks run |
| --- | --- |
| Before generation | Claims against the product truth. Rights: avatar licence tier and music licence |

| Before upload | Disclosure added. Final rights sweep |

## 5. The detail behind each check

### Check 1. Claims (lecture 6.2)

A claim is defensible if it is a real, documented spec you can check against the
product, or a description of the audience. It is not defensible if it is an outcome,
a number nobody measured, a study that does not exist, or an endorsement you do not
hold. A disclaimer or asterisk does not create the missing evidence.

| Question | Your answer |
| --- | --- |
| Every claim, spoken, on screen, in captions, in overlay text and in the landing page, listed and traced to the product truth | |
| Anything that is a number, a result, a medical or health statement, a comparison or an endorsement: where is the evidence, and who holds it? | |
| Would you say each claim out loud to a compliance officer? | |
| Anything that fails: rewritten to a sentence you can defend (not given an asterisk) | |

### Check 2. Rights (lectures 4.1 and 6.4)

One question, asked of everything in the frame that is not your own product.

| Element | The question | Evidence kept (file, screenshot, date) |
| --- | --- | --- |
| A face or voice | Licensed avatar tier that covers paid social, or documented consent for a real person | |
| Music | Is this track licensed for commercial, paid social use specifically, not just personal or organic use? | |
| A third-party brand or logo | Does showing it imply an endorsement or comparison nobody agreed to? If a real brand appears in your generated frame, did it need to be there at all? | |
| An AI-generated "actor" | The same licence-tier question as an avatar, whatever the tool calls it | |

Check which licence tier you are on before every campaign, not once when you signed
up.

### Check 3. Accuracy (lectures 3.3 and 4.4)

| Question | Your answer |
| --- | --- |
| Does the product match the real one's colour, cut, texture and detail? Has the generator "improved" a design detail? | |
| For video: did the product stay accurate through the last frame? Is the on-screen product your filmed clip? | |
| Is every overlay and caption identical to the product truth wording? | |
| Would the person who knows the product best recognise it? | |

### Check 4. Disclosure (lecture 6.3)

Lecture 6.3 describes platform labelling policies, and some local laws on synthetic
performers and AI transparency, as they stood when it was recorded. These change and
differ by place. This template does not repeat them as fact. Confirm what applies to
you for every campaign, and record it.

| Question | Your answer |
| --- | --- |
| Every platform and every country this batch will run in | |
| What each platform requires for AI-generated or AI-modified creative, from its current published policy (link and date checked) | |
| What local rules apply to synthetic performers or AI transparency where the ad runs, confirmed by whom (a name) and when | |
| Which assets in this batch are generated or AI-edited | |
| The label added: on-screen caption, platform flag, or both, and where | |
| Visible for the whole runtime, for video? | |

## 9. Honest test

- Did every check have a named owner, and could that person actually stop the batch?
- Did you run it on every ad, or only the ones you were worried about?
- Did anything fail? If nothing did, how hard did you look?
- Is any rule in section 5, check 4 something you assumed rather than confirmed today?
- Does the landing page say the same thing as the ads (B01, section 6)?
