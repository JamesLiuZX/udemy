@slide statement
kicker: Section 10 · The proof, not the archive
## Twelve artifacts sitting in a folder prove nothing. Four of them, walking one feature from idea to shipped, prove everything.
lead: A portfolio isn't a bigger pile of documents. It's the smallest set that shows the judgment behind them.

@narrate
You've built twelve real artifacts across this course: a PRD template,
a golden set, a rubric, a cost model, a risk register, a metric tree,
and more. Dumped into a folder and linked in an email, they prove you
attended a course. Selected and sequenced around one real feature, they
prove something an interviewer actually can't get from a resume line:
that you know what order the thinking happens in.

Most PM portfolios show a shipped feature and a nice screenshot. Almost
none show the eval rubric, the cost model, or the risk register behind
it, because most PMs never formally built one. That gap is exactly
where this course's artifacts stop being homework and start being a
genuine differentiator.

This isn't about hiding the other eight behind the four you lead with.
All twelve stay available, linked or attached, for anyone who wants to
go deeper. The four you actually walk through out loud, in the room,
are the ones doing the work of proof. The rest are there for the
person who asks a genuinely specific follow-up and wants to see more.

@slide table
kicker: The arc, not the archive
## Four artifacts, one feature, in the order the questions actually get asked

| Question | Artifact |
| --- | --- |
| What is it, and what's the bar | A01, the PRD |
| Does it actually work | A02/A05, golden set and rubric |
| Is it worth what it costs | A09, the cost model |
| Is it safe to ship | A11, the risk register |

@narrate
Pick one feature, real or from this course's exercises, and walk it
through these four questions in this exact order, because it's the
order a genuinely good interviewer already asks them in, whether or not
they've ever seen this table.

If you're choosing between a real feature from your own work and one
built entirely from this course's exercises, the real one usually wins,
even if it's smaller and less polished. Genuine judgement under real
constraints reads differently from a clean exercise, and most
interviewers can tell the difference within a few questions.

Resist the instinct to show all twelve artifacts because more feels
like more proof. It's the opposite. Twelve artifacts with no throughline
reads as a checklist completed. Four artifacts walking one feature from
spec to shippable reads as a way of thinking, which is the actual thing
being evaluated in the room.

@slide example
kicker: What's deliberately left out
::: example Held for a follow-up, not the main four
9.6's metric tree and 8.7's red-team pass. Both genuinely strong
artifacts, both better as an answer to a specific question than as
part of the opening four.
:::

@narrate
Why leave two strong artifacts out of the main four? Because a
portfolio walkthrough that tries to cover every section of this course
in one sitting stops being a story and becomes a syllabus recited from
memory. Four questions, answered well, beats twelve topics mentioned in
passing.

Notice, too, that the four-question sequence works because each answer
sets up the next question naturally. Once the PRD's threshold is on the
table, the golden set's pass rate is the obvious next thing anyone
would ask for. Once the pass rate is real, the cost number is what
makes it a business decision instead of a demo. The order isn't
arbitrary. It's the sequence a good question naturally produces.

@slide callout
kicker: The honest caveat
::: callout Be straight about this
Course exercises are not production history. ==Say plainly which
artifacts came from a real feature and which came from practice==, and
never let the framing imply otherwise.
:::

@narrate
Say the honest caveat plainly, because this is the exact doctrine this
whole course has run on, aimed one last time at you instead of a
feature you're building.

"I practised this discipline on a hypothetical feature to make sure I
could do it for real" is a completely legitimate, respectable sentence.
Letting an artifact's polish imply it came from a real shipped product
when it didn't is the one move that turns a genuine portfolio into
something a single follow-up question can quietly unravel. The honest
version survives every follow-up. The other kind survives exactly one.

This matters more than it might seem worth a whole caveat, because the
cost of getting caught is specific and hard to recover from. An
interviewer who catches one inflated claim doesn't just discount that
claim. They quietly re-evaluate everything else you said in the same
conversation, including the parts that were completely true.

@slide definition
kicker: Naming it precisely
::: definition A portfolio narrative
Four artifacts, one real feature, walked through in the order the
questions get asked, each one honestly labelled as real work or
practice.
:::

::: example Try this yourself
Pick your strongest artifact from this course. Write two sentences
explaining what question it answers and what real feature it was built
against.
:::

@narrate
That's the standard worth building the rest of the portfolio to, and
the exercise is worth doing today, on the artifact you're actually
proudest of.

Most people find the two sentences harder to write than the artifact
was to build, because naming the exact question it answers, precisely,
is a different skill from having built something that answers it
instinctively. That's worth practising before an interview room is the
first place you're doing it.

Do this for more than one artifact if you have time, not just your
favourite. The exercise gets easier by the third attempt, and the
version of you doing it a fourth time is the version actually ready for
a real interview room, not the version who wrote two good sentences
once and hoped the rest would follow naturally.

@slide bullets
kicker: Before you move on
## Two things worth doing now

1. Pick four artifacts and sequence them around one real feature
2. Label each one honestly: real work, or practice from this course

@narrate
Two things before you move on.

Pick the four and the order first. Use this lecture's table as the
starting sequence, and adjust it only if your actual feature's story
genuinely asks its questions in a different order.

Then label every artifact honestly, in writing, before anyone else
reads it. That label is what turns a portfolio into something you can
defend under any question, not just the ones you rehearsed.

Neither of these requires building anything new. Every artifact already
exists. This is entirely about selection and honesty, the cheapest,
highest-leverage work available to you in this entire section.

Next lecture is interview questions you can now answer, the specific
ones this course was built to prepare you for.
