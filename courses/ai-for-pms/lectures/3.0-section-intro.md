## Specifying an AI Feature
lead: The PRD that fails at QA, replaced with one acceptance criteria can actually test.

@narrate
Every section so far has been building toward this one. You have the
mechanism, and the vocabulary. Now the actual job: writing a spec an
engineer can build against, and QA can hold you to.

A normal PRD describes a feature. This section is about a different
document, one that describes exactly how you'll know the feature is
working, before a single line of it gets built.

@slide bullets
kicker: What's ahead
## Five ideas, then a document you'll actually use

1. Why a normal PRD quietly fails on an AI feature
2. Acceptance criteria written as evaluation thresholds, not adjectives
3. Specifying the golden dataset and what "good" means, precisely
4. A failure taxonomy, and where a human has to stay in the loop
5. The full PRD template, then writing your own for a real feature

@narrate
Five ideas, building in a straight line toward one deliverable.

You'll see exactly why "the AI should respond helpfully" isn't an
acceptance criterion, and what to write instead. Then the golden
dataset, the rubric, the failure taxonomy, and where a human has to
check the output before anything ships.

It ends with the complete PRD template, and you writing your own, for a
feature you're actually close to.
