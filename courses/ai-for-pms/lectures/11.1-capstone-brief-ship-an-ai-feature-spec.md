@slide statement
kicker: Section 11 · The capstone
## One feature. Six artifacts this course already taught you to build. Nothing new after this slide.
lead: This isn't a quiz. It's the work you'd actually do in month one of the job, done once, deliberately, with nothing left to guess at.

@narrate
Pick one AI feature idea, real if you have one at work, realistic if you
don't, and take it all the way from a written spec to a risk-assessed,
metric-instrumented plan, using six artifacts this course has already
taught you to build. Nothing about this capstone is new material. It's
the same assembly-under-a-deadline exercise 10.1 asked of a discovery
sprint, except the deadline is now yours to set and the scope is the
whole course instead of one week's tools.

Be honest with yourself about the time this actually takes. This isn't
a twenty-minute in-lecture exercise like the section workshops. Block
real time, a weekend is realistic, because six genuine artifacts for
one real feature is genuinely a few hours of work, not something to
rush between other tasks.

The next two lectures walk through one worked solution to this exact
brief. Don't open them until you've produced your own package first.
The value here is entirely in doing the work yourself before you see
anyone else's answer, the same way a golden set only tells you
something if you score it honestly before checking the key.

This is also the last point in the course where anyone hands you the
structure. Every artifact until now came with a lecture built around
it. From here, the only brief is this one, which is deliberately closer
to how the actual job works than anything else in this course has been.

## Six artifacts, one real feature

| Artifact | Where you built it |
| --- | --- |
| A01, the PRD | 3.7 |
| A02 + A05, golden set and rubric | 4.2, 4.3 |
| A09, the cost model | 7.2 |
| A10, the model scorecard | 7.4 |
| A11, the risk register | 8.1 |
| A12, the metric tree | 9.6 |

@narrate
These six are required regardless of what feature you pick, because
every AI feature needs the same six answers: what it is, whether it
works, what it costs, which model earns its place, what could go wrong,
and how you'll know it's working after launch. That's the whole course,
compressed to one page of deliverables.

Two more artifacts join the list conditionally, not by default. Add
5.7's RAG design doc and 5.4's retrieval scorecard only if your feature
actually retrieves from a knowledge base. Add 6.8's agent worksheet
only if it takes autonomous action. Forcing either one into a feature
that doesn't need it is exactly the mistake 10.5 warned against:
padding a package with artifacts that don't belong to the story you're
actually telling.

Notice, too, this list deliberately doesn't include every artifact this
course has produced. A03 and A04, the two eval harness formats, are
tools for building A02, not separate deliverables. Building the golden
set matters. Which spreadsheet or script you used to score it doesn't
need its own line in the package.

This six-artifact package is also deliberately larger than 10.5's
four-artifact portfolio walkthrough, and that's on purpose. The
capstone is where you build the whole thing. The portfolio is where
you later choose which four of these six earn a place in an actual
conversation. Build all six now. Learn which four to lead with later.

@slide two-col
kicker: What actually gets checked
## Six disconnected documents, and one coherent package

::: cols
:: card bad
### Six disconnected documents
- The PRD's threshold and the golden set's pass bar don't match
- The cost model's volume assumption isn't the PRD's actual scope
- Reads as six homework assignments about six different features
:: card good
### One coherent package
- Every number in the risk register traces back to the PRD's scope
- The metric tree's leaves are the metrics the PRD promised to move
- Reads as one feature, documented by someone who owns all of it
:::

@narrate
This is the actual signal worth optimising for, and it's not whether
any single artifact looks correct sitting on its own. It's whether all
six agree with each other, because that agreement is only possible if
you held the whole feature in your head while building every piece.

Check this yourself before you call the capstone finished. If your PRD
promises ninety-five percent and your golden set's pass rate is
measured against ninety, that's not a rounding difference, it's a
package that never got reread end to end. The same check applies to
volume: if the cost model assumes ten thousand monthly uses and the
PRD never mentions that number anywhere, one of the two documents is
wrong, and finding out which is exactly the work this exercise is
for.

This consistency check costs almost nothing compared to building the
six artifacts in the first place, and it's the part most people skip
under deadline pressure. Spend the last twenty minutes on it anyway.
It's the highest-leverage twenty minutes in the entire exercise.

@slide callout
kicker: The honest caveat
::: callout Be straight about this
The worked solution is one valid answer, not the only correct one.
==Two good capstones on the same brief can disagree==, provided each
one can defend its own numbers.
:::

@narrate
Say the honest caveat before you open the next two lectures, because a
capstone with exactly one right answer would teach the opposite lesson
from everything this course has built toward.

If your cost model assumes a different volume, your risk register
names a different top concern, or your feature idea is nothing like
the worked example's, none of that is a deviation to correct. It's
what real judgement looks like applied to a different feature under
different assumptions. The test was never whether you match the
worked solution's numbers. It's whether you can defend your own,
under a follow-up question, the exact standard 10.6 asked of an
interview room.

Use the worked solution the way 4.9 taught you to use a second rater:
as a calibration check on your own reasoning, not a key to mark
yourself against line by line.

@slide definition
kicker: Naming it precisely
::: definition A finished capstone
Six artifacts, one real feature, internally consistent with each
other, each number defensible under a follow-up question.
:::

::: example Try this yourself
Pick your feature right now, before you close this lecture. Write one
sentence naming it and why it's real enough to sustain six artifacts.
:::

@narrate
Do this before you move on to anything else, because the feature
choice is the one decision every other artifact depends on, and it's
the easiest step to postpone indefinitely if you let yourself.

Pick something substantial enough to need all six answers honestly.
A feature so simple that the risk register has nothing to say and the
cost model rounds to zero won't give you a real capstone, it'll give
you six thin documents about a feature that never needed this much
process in the first place.

If nothing from your own work fits, borrow one of this course's
running examples instead of inventing something from nothing: a
support ticket triage feature, a contract review assistant, a refund
approval agent. Any of them carries enough real stakes to need every
artifact on the list, honestly.

## Two things worth doing now

1. Pick your feature and write the one-sentence commitment now
2. Block real time for this: a weekend, not twenty minutes

@narrate
Two things before you move on.

Name the feature in writing, today, even if the rest of the package
takes until the weekend. The commitment is what turns this from a
lecture you watched into a project you're actually doing.

Then block the time honestly on your calendar. Six real artifacts
don't happen in the gaps between other work, and pretending they will
is how a capstone quietly never gets started.
