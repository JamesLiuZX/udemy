## Analytics for AI Products
lead: Section four measured quality before you shipped, on fifty cases you chose. This section measures value after you ship, on users you don't control.

@narrate
A golden set tells you whether the feature works. It can't tell you
whether anyone wants it, keeps using it, or trusts it enough to stop
double-checking the answer. That gap, between working and mattering, is
what this section closes.

By the end, you'll know which metrics actually survive contact with a
probabilistic feature, how to instrument one properly, and how to build
the metric tree that turns a pile of dashboard numbers into a single
story leadership can act on.

@slide bullets
kicker: What's ahead
## Five ideas, then the metric tree you'll actually use

1. Metrics that survive: adoption, acceptance, deflection
2. The instrumentation plan, built before launch, not bolted on after
3. A/B testing a feature that gives a different answer every time
4. Feedback loops and the data flywheel
5. Dashboards leadership actually reads, and the ones they don't

@narrate
Five ideas, building toward the same kind of deliverable every section
in this course has produced: something you take into a room and defend,
this time with a real number behind every claim.

You'll learn which metrics hold up for a feature that behaves
differently every time it runs, how to instrument before launch so
you're not guessing afterward, and how to test a change honestly when
the thing you're testing refuses to be consistent.

It closes with you building the metric tree itself, the one document
that turns every number this section teaches into a story someone
outside the room can actually follow.
